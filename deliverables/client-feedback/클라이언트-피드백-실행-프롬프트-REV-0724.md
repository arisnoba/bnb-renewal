## 1. 문서 사용법

이 문서는 원문을 단순히 옮긴 목록이 아니다. 각 요청을 다음 네 상태로 나누고, 구현 범위와 완료 조건을 명시한다.

| 상태 | 의미 | 처리 원칙 |
| --- | --- | --- |
| `확정` | 요청과 완료 조건이 비교적 명확함 | 현재 구현을 확인한 뒤 가장 작은 변경으로 처리 |
| `조사 필요` | 버그 원인 또는 기존 데이터 연결 규칙 확인이 선행되어야 함 | 재현 → 원인 규명 → 최소 수정 순서로 진행 |
| `자료 대기` | 문구, 이미지, 시간표 등 필수 입력이 아직 없음 | 구조만 임의 구현하지 말고 자료 수령 후 진행 |
| `결정 필요` | 요청의 의미가 둘 이상이거나 운영 정책 결정이 필요함 | 구현 전에 선택지와 영향을 정리해 확인 |
| `보류` | 사용자가 자료 또는 내용을 확인 중이거나 우선순위를 뒤로 미룸 | 사용자 재요청 전까지 구현하지 않음 |
| `사용자 처리 완료` | 사용자가 직접 수정한 항목 | 회귀 범위에서만 확인하고 중복 수정하지 않음 |
| `제외` | 이번 피드백 구현 범위에서 제거됨 | 별도 요청이 들어올 때 새 작업으로 진행 |

### 범위 해석 원칙

1. “탭/페이지 비활성화”는 **메뉴 또는 탭만 숨긴다**는 뜻으로 해석한다.
2. 비활성화 요청은 GNB의 데스크톱·모바일 메뉴를 함께 처리하고 기존 데이터는 삭제하지 않는다.
3. 숨긴 페이지의 직접 URL 접근은 현재처럼 유지한다.
4. “전 센터”는 아트·입시·하이틴·키즈·에비뉴센터를 기본 범위로 보되, 해당 기능이 없는 센터에는 억지로 적용하지 않는다.
5. 콘텐츠·이미지·정렬 변경은 기존 데이터를 파괴하거나 원격 운영 데이터를 직접 수정하지 않는다.
6. PDF에서 별도 TXT 또는 이미지 전달을 예고한 항목은 임의 문구나 임시 이미지로 대체하지 않는다.

### 3.1. 강사 센터별 관리 방식 문의 메시지

```text
강사 등록 및 노출 순서 관리 방식과 관련해 확인 부탁드립니다.

현재는 강사 정보가 통합 DB로 관리되어 동일 강사가 여러 센터에 노출될 경우, 센터별 노출 순서를 각각 조정하기 어려운 상태입니다. 개선 방식은 아래 두 가지가 가능합니다.

1. 동일 강사라도 센터별로 각각 등록
- 센터마다 소개 내용과 노출 순서를 완전히 독립적으로 관리할 수 있습니다.
- 다만 사진이나 경력 수정 시 같은 강사 정보를 센터별로 반복 수정해야 합니다.

2. 강사 정보는 한 번만 등록하고 센터별 노출 순서만 별도 관리
- 사진과 경력은 한 곳에서 관리하면서 센터마다 노출 여부와 순서를 다르게 지정할 수 있습니다.
- 중복 등록과 반복 수정이 적어 운영 측면에서는 이 방식을 권장드립니다.

센터별로 강사 소개 내용까지 서로 다르게 운영해야 한다면 1번, 강사 정보는 동일하고 노출 순서만 다르면 2번이 적합합니다. 실제 운영 방식에 맞는 방향을 확인 부탁드립니다.
```

## 4. 전 센터 공통

### COM-01. 기존 멤버십 전용 페이지의 URL·운영 정책 수립

- 상태: `보류·최후 순위`
- 현재 기본안: 공수가 적은 새 도메인 리다이렉트
- 원문: PDF 2쪽
- 현재 URL:
  - 멤버십 홈: <https://baewoo.co.kr/web/bbs/content.php?co_id=qr_academy_main>
  - 익명게시판: <https://baewoo.co.kr/web/bbs/board.php?bo_table=qr_community>
  - 스타카드: <https://baewoo.co.kr/web/bbs/content.php?co_id=qr_main>
- 사용자 흐름:
  - 수강생은 QR 코드로 접속한다.
  - 운영 직원은 기존 관리자 화면의 멤버십 경로로 접속한다.
  - 핵심 기능은 `스타카드 이용`, `익명게시판`이다.

#### 실행 프롬프트

```text
이 항목은 최후 순위로 보류한다. 재개 시 홈페이지 리뉴얼 이후에도 기존 멤버십 QR 사용자와 운영 직원이 중단 없이 접근할 수 있도록 URL·도메인 운영안을 조사하라. 현재 기본안인 새 도메인 리다이렉트를 우선 검토하되, 기존 QR URL 유지와 레거시 페이지 병행 운영의 영향도 비교하라. 정책 승인 전에는 레거시 시스템이나 운영 도메인을 변경하지 말라.
```

#### 완료 조건

- 기존 QR 인쇄물을 계속 사용할 수 있는지 명확하다.
- 수강생과 운영 직원의 접속 경로가 각각 정의되어 있다.
- 스타카드와 익명게시판의 데이터·인증 주체가 확인되어 있다.
- 도메인 전환 시 리다이렉트 규칙과 롤백 방법이 문서화되어 있다.


#### 완료 조건

- 성공한 저장 뒤 상담 문의 목록으로 이동한다.
- 실패한 저장 뒤 입력 내용이 보존된다.
- 권한별 관리자 흐름에 회귀가 없다.

```text
하이틴·입시·키즈센터의 CS 상담센터 운영시간을 평일 10:00~19:00, 점심시간 12:00~13:00, 주말 10:00~19:00로 변경하라. 아트센터 값은 변경하지 말라. 상담 신청, 입학안내, 푸터, 센터 정보처럼 운영시간을 중복 노출하는 모든 공개 위치를 검색해 같은 값을 사용하게 하라.
```

### MULTI-04. 하이틴·키즈의 6월 이후 게시글 추가 반영

- 상태: `보류·사용자 확인 중`
- 원문: PDF 42쪽
- 범위:
  - 변경: 하이틴·키즈센터
  - 제외: 아트센터

#### 실행 프롬프트

```text
사용자가 기준일과 원본 내용을 확인 중이므로 현재는 구현하지 않는다. 사용자가 내용을 확정해 다시 요청하면 하이틴·키즈 게시글을 원본 시스템에서 추가 반영하라. 실행 전에 정확한 기준일, 원본 DB/사이트, 대상 게시판, 중복 판정 키를 확인하고 먼저 로컬 dry-run 결과를 보고하라. 운영 반영은 별도 승인을 받은 뒤 진행하고 아트센터 데이터는 대상에서 제외하라.
```

#### 완료 조건

- dry-run에서 신규·중복·누락 건수를 확인할 수 있다.
- 재실행해도 중복 생성되지 않는다.
- 하이틴·키즈에만 반영되고 아트에는 영향이 없다.

## 14. 최종 완료 정의

각 작업은 다음 조건을 모두 충족해야 완료로 본다.

- 원문 PDF의 해당 페이지와 변경 결과를 대조했다.

- `npm run check:design`, `npm run typecheck`, `npm run lint`, 관련 테스트 결과를 보고했다.
- 운영 환경 변경이 필요한 항목은 로컬 검증과 별개로 명시적 승인을 받았다.
